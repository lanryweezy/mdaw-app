## 2025-02-23 - Avoid Expensive Try-Catch blocks in UI logic loops
**Learning:** In Dart/Flutter, using `try-catch` inside loops (especially for things that can easily be handled with `if` conditions or iteration) is a performance bottleneck. When finding elements in lists, standard `for` loops or `firstWhere` with `orElse` are much faster than relying on `firstWhere` to throw a `StateError` and catching it. Additionally, avoiding double iteration (e.g., using `.any()` to check if an element exists, followed by `.firstWhere()` to get it) is a simple O(N) instead of O(2N) optimization.
**Action:** When implementing searches in lists, especially in frequently called UI methods, prefer standard `for` loops or `firstWhere` with an `orElse` fallback to avoid the overhead of throwing and catching exceptions. Never use `.any()` and `.firstWhere()` on the same list when you can just find the item and return it.
